## Brand and copy decisions

The supplied identity uses Deep Graphite `#0F1F1E`, Warm Off-White `#F8F6F1`, Steel Blue `#6B8BA7`, and Stone Gray `#C9C5BC`. Light and dark SVG mark and lockup variants, a compact header lockup, monogram navigation mark, favicon, app icons, and Open Graph artwork use the same geometry. Responsive navigation switches from the full lockup to the compact lockup and then the monogram at narrow widths. Logo exports were visually checked at 16, 24, 32, 40, 48, 64, 128, 256 and 512 px; browser checks cover the three responsive variants in both themes. UI interaction colors use contrast-tested derivatives of the palette. The public name is exactly **Ajmir Aribam**.

The copy describes the work that source supports: server-owned totals, evidence-linked review, deterministic accessibility checks, civic workflow design and local prototype boundaries. It excludes unsupported school figures, business outcomes, production AI accuracy, legal authority, and private source paths. Social links use the supplied GitHub, LinkedIn, Instagram and X URLs.

The final human-copy pass starts the homepage with the products and systems behind them, follows with a restrained “Selected work” label, explains each case in product-first order, and presents Engineering as an evidence map. Repeated decorative project counts and section numbers were removed. The résumé and About page remain factual and recruiter-readable. Frameworks follow product context and engineering decisions. Maturity labels and known limits remain visible. Calls to action name the next step.

The user-supplied Verity, SCMIRN, AccessForge and Zam Zam captures were reviewed as visual evidence. The portfolio uses clean native diagrams for the new case hero surfaces so browser chrome and inaccessible attachment paths are not shipped as site assets.

## Quality review

- The release gate passed after removing the retired project and integrating the identity: strict TypeScript, ESLint/name check, production build, tests, browser checks, security scans, and Docker/Compose verification.
- Eight Playwright tests cover 19 content routes, all nine case pages, metadata, internal links, images, keyboard navigation, contact journey, both themes, and the removed route’s HTTP 404. Axe reports no automated A/AA violations on those routes in light and dark themes. The responsive sweep checks 14 widths with no document overflow; the new identity variants are separately checked at mobile and desktop widths.
- Full-page captures cover every route at 390, 768, 1440 and 1728 px in both themes. All route captures were visually reviewed in contact sheets; Home and Work were also reviewed at full size. The generated résumé PDF was included in the review. Generated screenshots and PDFs remain outside Git.
- Automated axe results are a gate signal, not an accessibility certification. Human screen-reader and physical-device review remain deployment follow-ups.
- Lighthouse was not available locally, so V8 performance scores, LCP, CLS and INP were not measured. No performance result from an earlier candidate is presented as a V8 result.

## Release boundary

The local candidate can be rebuilt and run with the repository’s existing Compose topology. It is not represented as deployed. The installed Render CLI returned `unauthorized` for `whoami`, and no deployment blueprint or hosting target is configured in the repository; there is no verified public URL. Production still requires a confirmed HTTPS origin, proxy/IP policy, database credentials and restore-tested backups, secret storage, staffed inquiry delivery or SMTP, retention scheduling, alerts, live-origin metadata review, human accessibility review and field monitoring. No push or production deployment is claimed in this review.
