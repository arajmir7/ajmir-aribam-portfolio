# Manual production deployment

Production uses one Vercel project with Vercel Services: public Next.js frontend, private FastAPI backend, Neon PostgreSQL, and Resend. Canonical origin: `https://ajmiraribam.me`. The root [`vercel.json`](../vercel.json) uses Vercel's current `services` and `bindings` configuration. Its frontend build command supplies the canonical `NEXT_PUBLIC_SITE_URL` so metadata generation can run even when a Vercel environment variable has not yet been added. Keep the matching Production variable configured as documented below. The frontend's `CONTACT_API_URL` is generated by the private binding at runtime. There is no backend public rewrite or `api.ajmiraribam.me` requirement.

Vercel currently documents Services and private bindings as beta/private beta and access may need to be enabled for the account. Confirm that Services appears as an available project framework before setup. If it is unavailable, stop: a separate backend project would change the requested architecture. Verify plan terms and quotas directly; no zero-cost assumption is made.

## Environment matrix

Set Vercel variables in the **Production** environment unless a broader scope is intentionally required. Do not import `.env.example` into Vercel; it contains local-only values.

### Vercel frontend service

| Variable                   | Value / source                                                                                |
| -------------------------- | --------------------------------------------------------------------------------------------- |
| `NEXT_PUBLIC_SITE_URL`     | `https://ajmiraribam.me`                                                                      |
| `CONTACT_ALLOWED_ORIGIN`   | `https://ajmiraribam.me`                                                                      |
| `CONTACT_INTERNAL_TOKEN`   | Random secret, at least 32 characters; identical backend value                                |
| `CONTACT_CLIENT_IP_HEADER` | `x-forwarded-for`                                                                             |
| `CONTACT_API_URL`          | Generated by the `frontend` → `backend` service binding in `vercel.json`; do not set manually |
| `VERCEL_GIT_COMMIT_SHA`    | Vercel system variable; enable system environment variables                                   |

`CONTACT_API_URL` is runtime-only and must not be renamed to `NEXT_PUBLIC_*`. The browser submits only to `/api/contact`.

### Vercel backend service

| Variable                 | Value / source                                                                                                                                         |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `APP_ENV`                | `production`                                                                                                                                           |
| `DATABASE_URL`           | Neon pooled runtime URL using `postgresql+psycopg://`, pooled host containing `-pooler`, and `sslmode=require`; use restricted application credentials |
| `CONTACT_INTERNAL_TOKEN` | Same secret as frontend                                                                                                                                |
| `CONTACT_ALLOWED_ORIGIN` | `https://ajmiraribam.me`                                                                                                                               |
| `RESEND_API_KEY`         | Resend API secret                                                                                                                                      |
| `CONTACT_EMAIL_FROM`     | Sender on the verified portfolio domain, e.g. `Ajmir Aribam <contact@ajmiraribam.me>`                                                                  |
| `CONTACT_EMAIL_TO`       | `arajmir7@gmail.com`                                                                                                                                   |
| `VERCEL_GIT_COMMIT_SHA`  | Vercel system variable; enable system environment variables                                                                                            |

Do not configure `MIGRATION_DATABASE_URL`, `CONTACT_API_URL`, or `RESEND_API_URL` in Vercel. `MIGRATION_DATABASE_URL` is explicitly rejected in production runtime. The code uses the official Resend API endpoint.

### Neon migration operator

| Variable                 | Value / source                                                                                                          |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------- |
| `MIGRATION_DATABASE_URL` | Direct Neon connection URI for a migration role with DDL privileges; keep in a password manager or protected shell only |

The operator URI must use TLS. Keep migration and runtime roles separate. Never put the direct URL into Vercel or Git.

### Optional CI and monitoring

The scheduled public smoke workflow accepts repository variables `PRODUCTION_URL=https://ajmiraribam.me` and `PRODUCTION_REVISION=<full commit SHA>`. These are not secrets. CI dependency audits and full-history Gitleaks scanning run without production credentials. No monitoring destination or live account checks are configured by this repository.

## 1. Review and enable Vercel Services

Connect the Git repository `arajmir7/ajmir-aribam-portfolio` to one Vercel project. Set the project framework to **Services** (or the current equivalent shown by Vercel), keep the project root at the repository root, and use the root `vercel.json`. The service entries set roots to `frontend` and `backend`, use Next.js and FastAPI detection, and point FastAPI at `app.main:app`. The backend intentionally has no public rewrite. The frontend declares the `CONTACT_API_URL` service binding.

Verify the build output shows both services and the binding. Inspect a deployment preview before production. Confirm the backend is not reachable from public paths and that frontend server functions receive a deployment-specific HTTPS `CONTACT_API_URL`. Vercel Services configuration is not cloud-verified by local repository checks.

Configure the variables above for both services. Use Vercel's Git commit SHA; the health route reports the frontend deployment revision. Select Vercel's Node.js 24 runtime for the frontend and Python 3.12 for the backend if the project UI requests a runtime version.

## 2. Provision Neon and apply migrations

Create a Neon project in a region near the Vercel functions. Create distinct application and migration roles. Grant the runtime role only schema usage, required table DML, and sequence privileges; deny schema DDL. Copy the pooled application connection string and ensure it has TLS. Store the direct migration URI only in the operator's protected shell.

From the repository root, with the backend development dependencies installed:

```sh
cd backend
MIGRATION_DATABASE_URL='postgresql+psycopg://<migration-user>:<password>@<direct-host>.neon.tech/<database>?sslmode=require' uv run alembic upgrade head
MIGRATION_DATABASE_URL='postgresql+psycopg://<migration-user>:<password>@<direct-host>.neon.tech/<database>?sslmode=require' uv run alembic check
MIGRATION_DATABASE_URL='postgresql+psycopg://<migration-user>:<password>@<direct-host>.neon.tech/<database>?sslmode=require' uv run alembic current
```

Use the exact direct URI from Neon, adapted to the SQLAlchemy `postgresql+psycopg` driver. `alembic current` must report `003_resend_message_id`; `alembic check` must report no new operations. Run from a trusted operator shell and do not put the URL in shell history on shared systems. These commands do not run automatically in the Vercel backend.

## 3. Configure Resend

Verify `ajmiraribam.me` (or a subdomain) as a sending domain in Resend and publish the exact DNS records Resend supplies. Create an API key scoped to that sending domain if available. Configure `RESEND_API_KEY`, `CONTACT_EMAIL_FROM`, and `CONTACT_EMAIL_TO=arajmir7@gmail.com` only on the backend service. Production configuration rejects sender addresses outside the portfolio domain and recipients other than the owner inbox. The visitor's address is used as `Reply-To`; it is never the sender. Do not use the Resend test sender for production.

## 4. Attach the canonical domain

Add `ajmiraribam.me` and `www.ajmiraribam.me` to the Vercel Services project. Set the apex as primary. Enter the exact DNS records Vercel displays for this project and account; do not use guessed IP/CNAME values. Preserve Resend mail records and remove only conflicting web records. Wait for Vercel domain verification and managed TLS. The app redirects `www` to the apex while preserving path and query; Vercel should redirect HTTP to HTTPS.

## 5. Deploy and smoke-test

Require CI to pass for the exact commit. Deploy that commit as production through Vercel. Confirm both services report the same deployment revision, the frontend public health route is ready, contact invalid/foreign-origin requests are rejected, and the backend has no public route. Verify canonical redirects and certificate status.

Run the public smoke script against the production revision:

```sh
PRODUCTION_URL=https://ajmiraribam.me EXPECTED_REVISION=<full-commit-sha> bash scripts/production-smoke.sh
```

The script does not submit a valid contact or send email. For a live delivery test, obtain explicit owner approval, submit one real inquiry through the form, then verify its database row, outbox state, Resend acceptance, received email, and visitor `Reply-To`.

## Rollback and recovery

Roll back the single Vercel deployment so frontend and backend stay on the same revision. Prefer a forward corrective Alembic migration; do not automatically downgrade production. Before launch, configure Neon retention/backup options and perform an owner-controlled restore drill into a separate branch or database. Local backup tooling checks do not verify Neon recovery. See [operations](operations.md).
